# Narrative plan

Audience: technical stakeholders, architects, engineering leadership, data/ML practitioners, and product stakeholders reviewing the POC.

Objective: explain what was implemented, why the architecture is trustworthy, where graph technology materially improves outcomes, and provide a clean structure for discussing each feature.

Narrative arc: operational facts → temporal correctness → reliable graph projection → reusable features → intelligence capabilities → governed decisions → demonstrable product surface.

Slides:

1. Technical title and thesis.
2. End-to-end locked architecture.
3. Temporal state and event correctness.
4. Transactional outbox and graph projection.
5. Why graph technology adds value.
6. Temporal plus graph feature contract.
7. Event memory, behaviour, and churn.
8. Recommendations, fraud, and forecasting.
9. Digital twin and decision engine.
10. Delivered UI/API surface and feature discussion path.

Source plan: repository architecture and feature documentation, implementation modules, tests, and existing UI screenshots. No external sources are required.

Visual system: dark navy technical canvas, cyan relationship lines, violet intelligence accents, and warm amber decision highlights. Poppins headings and Lato body text. Repeated layered-node motif visually links facts, relationships, and decisions.

Assets: use the three existing UI screenshots for customer intelligence, customer 360, and delivery status. Use editable PowerPoint objects for architecture, sequence, feature taxonomy, graph relationships, and all labels.

Image-generation plan: none required; the repository already contains product screenshots and the remaining visuals are technical diagrams that benefit from editable native objects.

Editability plan: all titles, body copy, labels, diagrams, cards, and status metrics remain editable. Screenshots are used only as evidence panels, never as a replacement for slide text.
